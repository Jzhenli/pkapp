- [ ] **3. app_hash 解耦确认**（★R-2★）— 建议：认可「明文 marshal 作指纹输入」；消费点实读核对列为档位 1 实施第一步（grep 全部消费点交评审过目）。
- [ ] **4. RFT 第一版范围与验收口径** — 建议：按现稿认可「私有实现符号清零，公开契约/数据形状仍可读」；红线（类体/参数/模块名）非保守而是正确。
- [ ] **5. traceback 取舍** — 建议：映射表永不落盘、不加开关（可选开关 = 还原表落盘 = 名字泄露面，与 RFT 目标矛盾）；排障走 dev 模式。
- [ ] **6. 威胁档位确认**（★R-6★）— 建议：正式确认接受 1A 动态 dump 残余风险（需物理接触运行环境 + 专职逆向，不在「防随手扒/魔改/批量分发」目标内）。此确认即安全边界声明。
- [ ] **7. 运维面迁移**（★R-7★）— 建议：K_master 准入写进 doctor + 一页文档；编译依赖不设独立排期（keylib 编译本就在构建流程内）。
- [ ] **8. §4.1.5 质量机制认可**（★R-10★）— 建议：双编译对拍 / 保守豁免 / 矩阵回归 / 覆盖率度量 四要素进 P1 验收清单；特性矩阵第一版控 30–40 用例。

## 四、背景提示（评审现场备查，非拍板项）

- **现状 `obfuscate.py` 实测结论**（对应 R-12 落地前置）：`transform()` 逐模块、局部计数器（line 755 `counter=[0]`），改名面仅 function-local 非参数绑定（低质量 RFT 基线，43 真名不动），跨模块 `a.foo` 属性改写 / import alias 同步**未实现**（`_lookup` module 层直接返回 None）。→ 当前是低质量 RFT 基线，P1-RFT 是实质升级而非微调。
- **当前实施范围** = 档位 1 + P1 + P1.5 + 纵深层；BCC（P2）整体后置。
- **"商用级"口径**：档位 1 + P1 到达**商用级混淆**（K 隔离 + 私有符号清零）；**未达 native 均衡点**（那是 BCC 的活，已后置）。对外表述按 §1.3 收敛。
